### 0.2 数据通道（全部在 `scan.ps1` 内执行）

| 代号 | 含义 | 硬性要求 |
|---|---|---|
| `CIM` | `Get-CimInstance`（默认 `root\cimv2`） | **禁用** `Get-WmiObject`、`wmic`（Win11 已移除 wmic）✅ |
| `CIM@ns` | 指定命名空间，如 `CIM@root\Microsoft\Windows\Storage` | 命名空间不存在时必须 catch，不能整脚本失败 |
| `REG` | `Get-ItemProperty` / `Get-Item` | 键不存在是常态，必须 catch |
| `CMD` | PowerShell cmdlet 或原生 exe（`Get-Counter`、`Get-NetFirewallProfile`、`netsh`、`fsutil`、`dotnet`、`wsl`） | 外部 exe 一律加超时；输出解析要考虑本地化 |
| `DX` | `dxdiag /x <file.xml>` 子进程 + XML 解析 | 仅走 P2 阶段；失败降级 `null`，不阻塞其它项 |
| `FS` | `Test-Path` / `Get-ChildItem` / `[IO.File]::Exists` | 只读，不写系统目录 |

### 0.3 序列化与类型约定（与 `types.ts` 逐条对齐）

1. 字段命名 **camelCase**，与 interface 字段名完全一致。
2. 容量/字节一律 `number`（bytes）；频率 MHz；百分比 `0–100` 的 `number`（不是 0–1）。
3. 时间一律 **ISO-8601 带时区偏移**：`2026-10-18T19:40:00+08:00`（PS：`.ToString("yyyy-MM-ddTHH:mm:sszzz")`）。
4. 拿不到：`string/number/bool → null`，`数组 → []`，**禁止** `""`、`"N/A"`、`"未知"`、`0` 冒充。
5. 布尔"三态"：`true / false / null`（如 `secureBoot`、`defenderRealtime`）。
6. `ScanMeta.warnings` 是给人看的短句数组，每条形如 `"TPM：Access Denied（需管理员）"`，**每条都要能对应到具体字段/采集器**。

### 0.4 状态与降级

| 状态（`CheckStatus`） | 含义 | 是否计入失败 |
|---|---|---|
| `pass` | 明确满足阈值 | 否 |
| `warn` | 满足硬性要求但有风险/可优化 | 否 |
| `fail` | 明确不满足硬性阈值 | **是** |
| `unknown` | 读不到 / 超时 / 命名空间缺失 / 服务异常 | 否（必须给出 `reason`） |

降级原则：
- **只有"明确读到不合格值"才允许 `fail`**；`null` 一律 `unknown`。C 页尤其严格：TPM 读不到 ≠ 不兼容。
- 所有"需管理员才有"的字段，在标准用户下写 `null` 并追加 `meta.elevationGains` 条目（例："原始 SMART 属性"、"BitLocker 状态"、"CPU/硬盘温度"）。
- 单项异常只记 `warnings`，**不中断整份报告**（对应 SPECS 的 fail-safe 思路）。

### 0.5 `scan.ps1` 契约（Rust 侧照此调用）

> **本节已于 v1.1.0 按实际实现重写**。早期草案里的「stdout 吐 JSON + `-EncodedCommand` 直接传脚本全文」
> 没有采用 —— 采集脚本有 2900+ 行 / 15 万字节，塞不进命令行，且中文必须走 Base64 文案块。
> 现行实现见 `src-tauri/src/scan.rs`。

```text
内嵌：   编译期 include_str!("../scripts/scan.ps1")，exe 不依赖外部脚本文件
落地：   每次扫描写 %TEMP%\emis-envcheck-<pid>-<nanos>.ps1（UTF-8 **带 BOM**）
调用：   powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass
         -EncodedCommand <base64(UTF-16LE 引导脚本)>
引导脚本：先切 [Console]::OutputEncoding = UTF8，再 & '<ps1>' -OutFile '<json>'，
         失败则 exit 1
工作目录：不指定（用默认），路径靠单引号转义后显式传参
stdout： 采集器**不写**（引导脚本只输出错误）；Rust 侧视为诊断信息
stderr： 诊断日志；Rust 按 UTF-8 解码，失败再按 GBK(936) 兜底，不解析内容
退出码： 0 = JSON 已生成；1 = 未捕获异常 / 写文件失败
超时：   Rust 侧 20s 硬超时（spawn + try_wait 轮询，超时 kill 并报错）
清理：   无论成败都删 .ps1 与 .json；另在每次扫描开始时清理 >1h 的残留
```

脚本内部要点（**以下为实际实现**）：

- 开头 `$ErrorActionPreference = 'SilentlyContinue'`，配合每段 `try/catch` 做软失败。
- 中文文案**不写在脚本正文**：全部以 Base64(UTF-8 JSON) 存在 `$script:TextB64` 的 `TEXT-BLOCK` 里，
  运行时解码成 `$script:T`。源真相是 `dev/texts.json`，改文案后跑 `dev/gen-texts.ps1` 重新注入。
  这样 `scan.ps1` 保持 **100% ASCII**，PS 5.1 无论按 ANSI 还是 UTF-8 解码都不会乱码/吞行。
- 输出：`ConvertTo-Json -InputObject $result -Depth 14` 后 `[System.IO.File]::WriteAllText($OutFile, $json, UTF8(no BOM))`。
  **必须显式 `-Depth`**（PS 5.1 默认 2，会截断嵌套对象）。
- 采集是**单文件顺序脚本**（约 21 个编号段落 + 30 个函数），不是「每域一个独立函数」；
  每段用 `Start-Timer` / `Stop-Timer` 记录分段时间，失败走 `Add-SectionFailure` 记 `warnings` 后继续。
- 批量 CIM 查询只在开头取一次（`$script:CimBase` 等），避免逐项查询拖慢。
- 外部命令（php -v / docker --version / wsl 等）统一走 `Invoke-CommandText`：1200ms 硬超时，
  且总耗时超过 6500ms 后**不再启动新探测**，保证 8s 预算。
- 版本号：`$script:CollectorVersion = '1.1.0'`（写进 `meta.collectorVersion`，文件头注释同步）。

### 0.6 执行时序

```text
P0  同步       权限判定、程序目录可写（Rust 侧）
P1  ≤5s        单次 scan.ps1：SystemInfo / Motherboard / CPU / Memory / GPU / Disk / Network / Security 基础 + Compat 基础
P2  首帧后     dxdiag（DirectX/WDDM/featureLevel）、事件日志、Get-HotFix、Get-Counter 采样、netsh wlan —— 可并入 P1 但要有各自超时；
               若 P2 拖慢首屏，则拆成第二次 `scan.ps1 -Stage 2` 调用（Rust 发两个命令，前端分别合并）
P3  用户触发   以管理员重启（`meta.isAdmin=true`）→ 补原始 SMART、BitLocker、Get-Tpm、温度
```

### 1.10 健康评分 → `ScanResult.score`（`HealthScore`）

**契约约束**：`parts` 恰好 5 项，`key ∈ {cpu, memory, storage, gpu, system}`，**`weight` 之和 = 1**，`level ∈ {excellent, good, fair, poor}`。

| key | label | weight | 打分（0–100） | 依据字段 |
|---|---|---|---|---|
| `cpu` | CPU | 0.20 | 核数/线程/主频分档 + 负载修正 | `cpu.physicalCores`、`logicalCores`、`baseMhz`、`usagePct` |
| `memory` | 内存 | 0.20 | 容量阶梯 + 使用率 + 是否跑满标称频率 | `memory.totalBytes`、`usedPct`、`modules[].ratedMhz/speedMhz` |
| `storage` | 存储 | 0.25 | 介质分（NVMe 100 / SSD 85 / HDD 45）与健康度按 6:4 加权 + 剩余空间 | `disks[].mediaType`、`healthPct`、`volumes[]` |
| `gpu` | 显卡 | 0.10 | 型号分档（借鉴 SPECS 分档表 ✅） | `gpus[].name`、`discrete` |
| `system` | 系统 | 0.25 | 100 起扣：build < 19045 −20、Win10 EOL −10、异常设备每个 −5（上限 −15）、电源计划节能 −5、UAC 关闭 −5、近 7 天非正常关机每次 −10（上限 −30）、有 minidump −10 | `system.build`、`system.powerPlan`、`security`、`meta.warnings` 等 |

- `total = Σ(score × weight)`，四舍五入到 1 位小数；`level`：`≥90 excellent`、`≥75 good`、`≥60 fair`、其余 `poor`。
- `note` 一句话依据（如"NVMe + 健康度 98%，剩余 412 GB"）。
- **缺失项不参与加权**：某子项关键字段为 `null` 时，该子项标记为不参与、其余权重归一化后计算，并在 `note` 注明"数据不全"（避免把"没权限"算成低分）。
- 评分与建议文案在 `scan.ps1` 内计算；前端只渲染（保持"PS 产出完整 `ScanResult`、Rust 透明转发"的契约）。

| `uefi` | UEFI 固件 | 需要 UEFI 引导 | `motherboard.firmwareMode` | `"UEFI"` | `"UEFI"` | UEFI pass；Legacy fail；`null` unknown |
| `dx12` | DirectX 12 | 显卡支持 DX12（feature level ≥ 12_0） | `runtime.directx.featureLevel` / `d3d12` | `featureLevel ≥ 12_0` 或 `d3d12=true` | `"12_1"` | 满足 pass；明确 <12_0 fail；`null` unknown |
| `wddm` | WDDM 驱动模型 | 至少 WDDM 2.0 | `runtime.directx.wddm` | `≥ 2.0` | `"3.1"` | ≥2.0 pass；1.x fail；`null` unknown |
| `gpt` | 系统盘分区表 | 需要 GPT | `MSFT_Disk WHERE IsSystem=TRUE → PartitionStyle` | `= 1 (GPT)` | `"GPT"` / `"MBR"` | GPT pass；MBR warn（可 MBR2GPT 但需备份）；`null` unknown |
| `osVersion` | 系统版本 | Windows 10 2004（19041）及以上，推荐 Win11 | `system.build` + `displayVersion` | build `≥ 19041` | `"24H2 (26100)"` | Win11 pass；Win10 ≥19041 warn+EOL 提示；<19041 fail |
| `display` | 显示设备 | 720p 以上、8bit 色深、≥9 英寸 | `gpus[].resolution`、`displays[].sizeInch` | 1280×720 / 8bpc / 9" | `"2560x1440"` | 满足 pass；不足 warn（软要求，不判 fail） |
| `sse42` | 指令集 SSE4.2/POPCNT | 支持 SSE4.2 与 POPCNT | `cpu.instructions` | 两者都在 | `"支持"` | 都在 pass；明确缺 fail；空数组 unknown。**依据未取得官方文档（❓），默认当作"信息项"而非硬性 fail** |

### 3.3 CPU 白名单策略（三层，避免硬编码全表）

1. **精确表**：`$SUPPORTED_CPU_PATTERNS` 数组（型号前缀/正则），人工维护常见型号（Intel 8–14 代桌面/移动、Core Ultra；AMD Ryzen 2000/3000/4000U/5000/7000/8000、Ryzen 7040 等）。
2. **代际兜底**（仅在精确表未命中时用）：
   - Intel `Core i3/i5/i7/i9`：型号数字 `≥ 8000` → 支持（如 `i5-8400`、`i7-10700`、`i9-13900K`）；
   - Intel `Core Ultra 5/7/9` → 支持；
   - Intel `Pentium / Celeron / Atom` → **默认不支持**（微软名单仅个别例外，需查表）；
   - AMD `Ryzen 3/5/7/9`：型号首位 `≥ 2` → 支持（`2600/3600/5600/7600`），`4xxx`（移动 Zen2）→ 支持；`Athlon 3000G` 等需查表；
   - 其它（Xeon、移动端特殊型号）→ 无法判定。
3. **兜底**：解析失败或未命中 → `unknown`，`reason = "无法判定：CPU 型号「{brand}」不在内置支持列表内，请对照微软官方处理器列表核对"`，`detail` 附官方链接。**绝不自动 fail**。

> 理由：微软名单随版本更新，硬编码全表必然过期；三层结构可维护、可解释、可回退。

### 3.4 `verdict` 与计数

| 条件（优先级从上到下） | `verdict` | 前端主色/文案 |
|---|---|---|
| `failCount > 0` | `blocked` | 绯红 `#c23a55`：「存在不兼容项」 |
| `failCount == 0 && (warnCount > 0 \|\| unknownCount > 0)` | `warn` | 琥珀金 `#e8b04b`：「可升级，建议先处理以下项」/「部分项目无法判定」 |
| 其余（全 pass） | `ok` | 玫瑰粉 `#f6a5b8`：「满足要求」 |

- `passCount/warnCount/failCount/unknownCount` 必须等于 `items` 中对应状态数（脚本内自检，防止漏项）。
- 页脚强制显示："共 N 项，通过 X / 警告 Y / 不通过 Z / 无法判定 W"，并对 `unknown` 提供"以管理员重新检测"入口。

### 3.5 修复指引（`detail` 长文案，前端展开）

| id | 指引要点 |
|---|---|
| `tpm20` / `tpmState` | 重启进 BIOS/UEFI（Del/F2/F10）→ Security / Trusted Computing → 启用 TPM 2.0 / PTT / fTPM → 保存重启。老主板无 TPM 2.0 → 无法软件修复。 |
| `secureBoot` | BIOS → Security → Secure Boot → Enabled；灰色不可改时先设置管理员密码或关闭 CSM。 |
| `uefi` | 当前为 Legacy 引导。切 UEFI 通常需要 MBR2GPT 转换分区（**务必先完整备份**）或重装系统。 |
| `gpt` | 系统盘为 MBR。可先 `mbr2gpt /validate /allowFullOS` 检查（只展示命令，**我们不代为执行**）。 |
| `cpuModel` | CPU 不在支持列表。可继续使用当前系统；升级需更换硬件。 |
| `memSize` | 内存低于 4GB，可升级内存条；板载内存机型无法升级。 |
| `diskSpace` | 系统盘容量不足 64GB，需更换更大容量硬盘；若只是可用空间偏少，清理临时文件即可。 |
| `dx12` / `wddm` | 先更新显卡驱动；仍不满足则需更换显卡。 |
| `osVersion` | 先升级到 Win10 2004（19041）以上并装最新补丁，再考虑升级 Win11。 |

## 5. `scan.ps1` 结构建议

```text
scan.ps1
├─ 常量区：$COLLECTOR_VERSION / 内存类型映射 / BusType 映射 / CPU 白名单
├─ 通用工具：Add-Warning、Invoke-Safe（try/catch 包装）、ConvertTo-Iso、Get-RegValue
├─ Get-SystemInfo            → SystemInfo
├─ Get-MotherboardInfo       → MotherboardInfo（含 firmwareMode/secureBoot/tpm）
├─ Get-CpuInfo               → CpuInfo
├─ Get-MemoryInfo            → MemoryInfo（含 modules）
├─ Get-GpuInfo               → GpuInfo[]（含注册表显存修正）
├─ Get-DisplayInfo           → DisplayInfo[]（WmiMonitorID + EDID 兜底）
├─ Get-DiskInfo              → DiskInfo[]（Win32_DiskDrive + MSFT_PhysicalDisk + Reliability + 卷关联）
├─ Get-NetworkInfo           → NetworkInfo（WMI + netsh wlan + 连通性探测）
├─ Get-RuntimeInfo           → RuntimeInfo（.NET/VC++/DX/WebView2/工具链/WSL）
├─ Get-SecurityInfo          → SecurityInfo（SecurityCenter2/防火墙/UAC）
├─ Get-CompatResult          → CompatResult（消费上面各对象，不重复查询）
├─ Get-HealthScore           → HealthScore（消费上面各对象）
└─ 组装 ScanResult → ConvertTo-Json -Depth 12 -Compress → [Console]::Out.Write
```

- 依赖顺序：`Compat` 与 `Score` 必须在其它对象之后计算（纯内存运算，不触发新查询）。
- `dxdiag` 放在最后单独执行，失败只影响 `runtime.directx.wddm/featureLevel` 与 `compat.dx12/wddm`。
- 每个 `Get-*` 自带计时，汇总进 `meta.scanMs`（含分项耗时可选写入 `warnings` 便于调优）。

| 阶段 | 目标 | 手段 |
|---|---|---|
| `scan.ps1` 总耗时 | ≤ 5s（标准用户）；≤ 8s（管理员） | 合并 CIM 查询、避免重复遍历、`Get-ComputerInfo` 仅在兜底时调用 |
