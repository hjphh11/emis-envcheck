## 0. 一句话结论

我们不需要发明产品结构：**SPECS 提供"页签式体检 + 0-100 健康分 + 免管理员降级 + 多格式报告"的完整骨架，WhyNotWin11 提供"逐项通过/不通过 + 原因 + 修复指引"的兼容性清单范式，systeminformation 提供 Windows 字段清单与权限限制的权威参照（注意：本项目最终不直接使用它，见 §0.1）**；三者叠加足以覆盖 A/B/C 三页签，其余项目只补细节（安全状态、磁盘健康、便携形态、传感器取舍）。

三个最关键的借鉴点：

1. **asInvoker + 分级降级**（SPECS）：绝不为传感器/TPM 提权而破坏"双击即用"；拿不到的字段显示"需管理员/不支持"，状态栏提示，而不是报错或伪装成 0。
2. **四态判定 + 原因文案 + 修复指引**（WhyNotWin11）：兼容性项用 `通过/警告/不通过/无法判定` 四种状态（不是布尔），每条不通过都配"为什么"和"怎么办"。
3. **通用事实模型 + 异步填充**（SPECS）：所有页面用同一种 `InfoGroup / InfoItem(name, value, severity)` 结构渲染，首屏 <2s 先出窗口，采集在后台并发填充，同一份数据直接驱动搜索、评分和报告导出。

### 0.1 本项目技术栈（调研期间已确定，直接决定"借鉴什么、不借鉴什么"）

调研开始时技术栈未定，调研过程中仓库里已出现骨架：**Tauri v2 + React 19 + Vite 8 + Tailwind 4 + Rust**（`src-tauri/`、`package.json`），并且 `src/types.ts` 已经定义了唯一数据契约（`ScanResult` / `CheckStatus` 四态 / `HealthScore` 五项权重），注释明确"**采集器 = PowerShell 脚本 `scan.ps1`，Rust 侧只做透明转发 + 少量补算**"。因此：

| 结论 | 说明 |
|---|---|
| systeminformation（Node 库）**不能直接用** | 后端是 Rust，不是 Node；它的价值转为**字段清单 + Windows 权限/性能限制的参照**（§6） |
| 采集层 = 单次 PowerShell 脚本 | 所有检测项必须能在 PowerShell 5.1 里跑通；`Get-CimInstance` 取代 `wmic`/`Get-WmiObject` |
| dxdiag / netsh / fsutil / dotnet / wsl 都是 PowerShell 侧子进程 | 需超时、需处理本地化输出 |
| 渲染层 = WebView2 | **Win10 1803+ / Win11 预装**（Tauri 官方文档 ✅）；绿色版必须把"WebView2 缺失"作为启动前置检查 |
| 前端已有 `@fontsource/zcool-xiaowei`、`@fontsource/ma-shan-zheng` | 字体离线内嵌，不依赖系统安装（与"绿色版"契合） |
| 报告形态 | 优先 JSON/Markdown/HTML；PDF 暂不做（Tauri 侧体积敏感，可用系统打印） |

> 因此下文"我们要不要抄"均以该栈为前提；`检测项清单.md` 已按 `src/types.ts` 逐字段对齐。

### 1.1 页面划分（可直接照搬的信息架构）

Dashboard / CPU / Motherboard / Memory / Graphics / Operating System / Storage / Benchmarks / Sensors / Live Monitor / Network / USB & Audio / System Score，外加：全局搜索（在所有已采集事实中即时过滤）、强调色切换、Export Report（HTML/PDF/JSON/CSV/TXT）。✅

### 1.2 可借鉴的工程决策（比页面更值钱）

- **通用事实模型**：几乎每个页面都渲染 `InfoGroup` 卡片里的 `InfoItem(name / value / severity)` 行。收益是三件事免费拿到：一套 `SectionView` 复用全部页面、全局搜索只需遍历 items、报告导出格式统一。✅ 这一条直接决定我们的数据层设计。
- **Everything is fail-safe**：`Wmi.Query` 永不抛异常，每个 collector 按设备隔离错误，缺电池/缺 TPM/无 SMART 权限时返回 `n/a` 或省略字段，程序不会因为"这台机器没有某个硬件"而崩。✅
- **Async-first loading**：窗口立即显示，`MainViewModel.LoadAsync` 在线程池上 fan-out 所有 collector 并 await，慢项（LibreHardwareMonitor 打开、评分）放到首帧之后。"启动 < 2s"指的是窗口可见，不是扫描完成。✅
- **Elevation 降级策略**：需要管理员的项（原始 ATA SMART 属性表、CPU 封装温度、风扇转速、TPM 状态、BitLocker）在标准用户下显示 `n/a`，状态栏显示 "Standard user — some sensors limited"，不弹提权框、不失败。✅
- **报告**：`ReportService` 把同一份 `ReportData` 快照序列化成 TXT/CSV/JSON/带内联 CSS 条形图的 HTML/PDF。✅ 我们的导出层可以照这个思路做，但**首版只做 JSON + Markdown + HTML（打印用），不引入 PDF 库**，省体积。

### 1.3 系统评分 0-100 的算法（源码已核对，✅ 这是本轮最有价值的产出）

`ScoreService.Compute()` 先算 5 个子项，**总分 = 5 项算术平均**，再输出"人话建议"列表：

| 子项 | 算法（源码实值） | 建议触发条件 |
|---|---|---|
| CPU | 有基准测试：`min(100, 多核分/120)`；无基准：`min(100, 核数*8 + 主频MHz/100)`；检测到降频 **-10** | 双核及以下 → 警告；降频 → "查散热/积灰" |
| RAM | 容量阶梯：`≥64G→100 / ≥32G→92 / ≥16G→80 / ≥8G→55 / ≥4G→30 / 其它→15`；内存带宽 <10 GB/s **-10** | <16G → 警告；`Speed > ConfiguredClockSpeed+100` → "去 BIOS 开 XMP/EXPO" |
| 存储 | 基准分 NVMe 95 / SSD 80 / HDD 40，再与"最差磁盘健康度"**各占 50%** 加权 | 系统盘是 HDD、卷占用 >90%、健康度降级 |
| GPU | 型号字符串分档取最高：RTX40/50、RX7xxx → 98；RTX30、RX6xxx → 90；RTX20、GTX16、RX5xxx → 75；GTX/RX → 60；ARC → 70；Quadro/RTX A/Radeon Pro/FirePro/Tesla → 55；Iris → 45；UHD/HD Graphics → 30；AMD APU → 40；无法识别独显 → 35 | 仅核显 → "办公够用，游戏/GPU 计算受限" |
| Windows 配置 | 100 分起扣：build < 19045（Win10 22H2）**-20**；SSD 上 TRIM 关闭 **-15**；电源计划为"节能" **-10** | 构建过旧、TRIM 关闭、节能模式、BIOS 超过 5 年 |

**我们要不要抄**：抄算法骨架与"建议文案与扣分同源"的设计；改进两点——① 我们的权重不平均（存储/稳定性更重）；② **子项数据缺失时按已知子项权重重归一化，而不是当 0 分**（否则无独显的办公机会被误判得很低）。

### 1.4 存储/SMART 管线（B 页签直接可复用）

1. `Win32_DiskDrive` 枚举物理盘，join `MSFT_PhysicalDisk` 拿介质/总线类型，ASSOCIATORS 关联分区→卷，`MSFT_Disk` 拿分区表类型（MBR/GPT），`fsutil behavior query DisableDeleteNotify` 拿 TRIM。✅
2. `MSFT_StorageReliabilityCounter` 提供温度、通电时长、磨损（Win10+，**通常标准用户可读**）；`MSStorageDriver_FailurePredictData/Status`（`root\wmi`）提供原始 ATA SMART 属性（**通常需要管理员**）。✅
3. LibreHardwareMonitor 补 NVMe 温度、Percentage Used、Spare、读写总量。✅
4. `HealthAnalyzer` 把合并后的数据换成 Health% / Remaining Life% / Performance%，并附人话说明与 SSD 寿命预估。✅

**结论**：我们首版只做"WMI 可靠计数器 + SMART 状态"这一层（免提权），原始属性表与传感器列为"可选深度检测"。

### 1.5 明确不抄的部分

- WPF/MVVM 本身（我们 UI 是暖色玻璃拟态，技术栈另定）。
- 基准测试（CPU/内存/磁盘跑分）：写入 ~0.5 GB、耗时数秒、结果波动大，与"检测"定位冲突，且容易引发用户对"跑了什么"的顾虑。
- 64 MB 单文件体积：我们的绿色版应显著更小。
- 未签名的 SmartScreen 警告：属于它自认的局限，我们至少要准备"首次运行提示"文案。

## 2. WhyNotWin11（C 页签的判定清单范式）

| 项 | 内容 |
|---|---|
| 仓库 | <https://github.com/rcmaehl/WhyNotWin11> |
| 协议 | LGPL-3.0（README 明示）✅ ⚠️ 注意：LGPL 不宜直接把它的 AutoIt 代码搬进我们的代码库，**只借鉴清单结构与文案** |
| 技术栈 | AutoIt3 编译为单 exe；WinPE / Windows 8.1 起可运行；支持 `/force` 强制运行 ✅ |
| 相关文件 | 英文语言包 <https://github.com/rcmaehl/WhyNotWin11/blob/main/Langs/0409.lang>、主程序 <https://github.com/rcmaehl/WhyNotWin11/blob/main/WhyNotWin11.au3> |

### 2.1 检测项（11 项，语言包与主程序 `$hLabel[11]` 双向核对一致 ✅）

Architecture / Boot Method / CPU Compatibility / CPU Core Count / CPU Frequency / DirectX 12 and WDDM 2 / Disk Partition Type / RAM Installed / Secure Boot / Storage Available / TPM Version。

### 2.2 呈现形式（最值得抄）

- **四态状态图标**：`iPass / iFail / iWarn / iUnsure`，对应 `通过 / 不通过 / 警告 / 无法判定`。✅ 比布尔值强得多，尤其适合"检测不到"这种既非通过也非不通过的情况。
- **每项右侧是"结果 + 原因"**，例如 `TPM 2.0 Detected`、`Disabled / Not Detected`、`TPM 1.2 Not Supported`、`Clean Install May Be Required`、`GPT Not Detected`、`Check Timed Out`、`Error Accessing List`、`Check Skipped`。✅
- **可点击的修复指引**：Convert Disk to GPT、Enable TPM、Enable Secure Boot、Skip CPU && TPM 等按钮，一键把用户送到对应说明。✅ 我们只给"操作步骤"，**不代用户改系统设置**（安全 + 绿色版定位）。
- **每项可跳过**：`/skip` 参数 + 界面 Skip 勾选，避免单项超时拖垮整体；另有 `Check Timed Out` 状态。✅ 对应我们的"per-collector 超时 → unknown"。
- **双模式**：Win11 升级兼容性 与 Feature Update 兼容性（`$bFUC` 分支），并区分 "可原地升级" 与 "需 Clean Install"。⚠️ 我们首版只做一种模式。

### 2.3 判定实现细节（源码片段核对 ✅）

- DirectX 检查**跑 `dxdiag` 子进程**、异步等待（`While IsArray($aResults[5][0]) ; Wait for DirectX Check to complete`），并设超时；WinPE 下没有 DirectX 组件时**回退到 GPU 型号/HWID 匹配**。→ 说明"dxdiag 解析 + 型号兜底"是被验证过的组合。
- Secure Boot 三态：`Enabled` / `Supported`（支持但未启用）/ `Disabled / Not Detected`。
- TPM 结果码 `0/1/2/3` 分别映射：未检测/版本不满足（显示实际 TPM 版本）/版本不满足/状态错误（判为 unsure）。
- 存储检查：`DriveSpaceFree <= DriveSpaceTotal/10` 时追加 "Clean Install May Be Required" 提示——即**空间充足性同时影响"能否升级"和"是否需要重装"**。
- CPU 频率兜底读注册表 `HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0\~MHz`。✅

### 2.4 风险

源码仍 `#include "Includes\_WMIC.au3"` 且界面有 "Loading WMIC" 文案；**Win11 已移除 WMIC 默认组件**，这条实现路径不能照抄（其内部是否已改 CIM 未逐行核验 ⚠️）。我们自己统一用 `Get-CimInstance`。

### 2.5 我们要不要抄

抄：11 项清单 → 扩展成我们 C 页签的 13-16 项；四态语义；"原因 + 修复指引"；逐项超时；dxdiag + 型号兜底。不抄：AutoIt、WMIC、/force 之类注入式绕过。阈值以微软官方为准（见 §7）。

## 4. NWinfo（便携开源硬件查看器，非 WMI 路线）

| 项 | 内容 |
|---|---|
| 仓库 | <https://github.com/a1ive/nwinfo>（已确认；另有 DeepWiki <https://deepwiki.com/a1ive/nwinfo>） |
| 协议 | **Unlicense**（公共领域，最宽松）✅ |
| 技术栈 | C / Win32；`gnwinfo.exe`（GUI，Win7+）与 `nwinfo.exe`（CLI，WinXP+），x86+x64 ✅ |
| 采集路线 | **不依赖 WMI**：直接读 SMBIOS / CPUID / PCI / SPD / EDID / S.M.A.R.T.（经其 `libcdi`，派生自 CrystalDiskInfo）✅ |
| 输出 | JSON / YAML / LUA / TREE / HTML，支持 `--human`、`--hide-sensitive`、`--cp=UTF8` ✅ |
| 权限/驱动 | 大多数字段免驱动；CPU 温度、SPD、IMC 等需加载驱动（搜索顺序 `CPUZ162 → NwHwIo → PawnIO`），PawnIO 需单独安装且要求 Win10 1809+ x64 ✅ |
| 传感器 provider | 内置 CPU/GPU/DIMM/SMART/DISK/NET/IMC，**也可读 LHM、HWiNFO、GPU-Z 的共享内存** ✅ |

### 4.1 可借鉴点

1. **"无 WMI"作为 fallback 路线**：当 WMI 服务异常、命名空间被策略禁用、或目标机是精简系统时，直接读 SMBIOS/CPUID 反而更稳。我们的 Node 层不重造这套，但可以保留"外部 nwinfo.exe 可选增强"的接口设计（见 §4.3）。
2. **报告格式与脱敏**：`--format=json` + `--hide-sensitive`（隐藏 MAC 与序列号）→ 我们导出报告**默认脱敏，页面上提供开关**。✅
3. **驱动即"可选增强"的分层**：无驱动仍可用，只是部分字段缺失——这正是绿色版该有的权限模型。✅
4. **单位与人类可读**：`--human`、`--temp-unit=C/F/K`、`--bin=NONE/BASE64/HEX` → 我们内部统一 SI 单位 + 展示层格式化。

### 4.2 体积与合规提醒

它的发布包含 `nwinfo.exe`、`libcdi.dll`、驱动安装器、`*.ids` 数据库等多个文件——**不符合我们"单 exe 绿色版"的体积目标**。若未来引用，务必注意 `libcdi` 派生自 CrystalDiskInfo 的许可条款（❓本轮未核验 libcdi 的具体协议，最安全的做法是**只在外部进程调用其 exe，不链接其 dll**）。

### 4.3 我们要不要抄

不内嵌；只抄设计：无 WMI 的兜底思路、JSON 报告结构、脱敏开关、驱动可选分层、CLI/GUI 双形态思想。

### 5.1 结论：**不集成，只借鉴分层**

- 传感器读取依赖内核级硬件访问组件（NWinfo 文档侧证：这类能力普遍要靠 PawnIO/自有驱动并需单独安装，且容易触发杀软误报 ✅）。绿色版双击即用 + 不装驱动 + 不弹 UAC，与它天然冲突。
- 借鉴：**"能力开关"模型**（哪个硬件类别采集、哪个不采集）+ **传感器作为可选增强层**（用户点"深度检测"再提权）+ **共享内存对接**（若用户本机已装 LHM/HWiNFO，可读取其共享内存拿到温度，而不用我们自己装驱动——NWinfo 已实现并文档化这条路径 ✅）。
- 许可：MPL-2.0 是文件级 copyleft，**进程内链接其库会带来源码可得义务**；进程外/共享内存交互则无此问题。若最终不用，风险为零。

| 项 | 内容 |

### 6.1 它能拿到的字段（Win 列已核对，✅ 摘自官方 README/文档表格）

- `system()`：manufacturer / model / version / serial / uuid / sku / virtual / virtualHost
- `bios()`：vendor / version / releaseDate / revision / serial
- `baseboard()`：manufacturer / model / version / serial / assetTag / memMax / memSlots
- `chassis()`：manufacturer / model / type / serial / assetTag / sku
- `cpu()`：manufacturer / brand / speed / speedMin / speedMax / cores / physicalCores / processors / socket / vendor / family / model / stepping / revision / flags / virtualization / cache{l1d,l1i,l2,l3}
- `cpuCurrentSpeed()`：avg / min / max / cores[]（⚠️ 见 6.2 的 Windows 限制）
- `cpuTemperature()`：main / cores[] / max（⚠️ Windows 常无值）
- `mem()`：total / free / used / active / available / swaptotal / swapused / swapfree
- `memLayout()`：size / bank / type / clockSpeed / formFactor / manufacturer / partNum / serialNum / voltageConfigured / voltageMin / voltageMax
- `battery()`：hasBattery / designedCapacity / maxCapacity / currentCapacity / voltage / percent / isCharging（部分字段仅 Mac）
- `graphics()`：controllers[].vendor/model/bus/vram/vramDynamic/temperatureGpu；displays[].vendor/vendorId/deviceName/model/productionYear/serial/displayId/main/connection/sizeX/sizeY/pixelDepth/resolutionX/resolutionY/currentResX/currentResY/currentRefreshRate
- `osInfo()`：platform / distro / release / codename / kernel / arch / hostname / fqdn / codepage / logofile / serial / build / servicepack / **uefi** / hypervisor / remoteSession
- `diskLayout()`：device / type(HD/SSD/NVMe) / name / vendor / size / bytesPerSector / firmwareRevision / serialNum / interfaceType / **smartStatus** / temperature / smartData（`smartData` 需 smartmontools ≥7.0）
- `blockDevices()`、`fsSize(drive)`、`fsStats()`、`networkInterfaces()`、`networkInterfaceDefault()`、`wifiInterfaces()/wifiConnections()`（SSID/BSSID/channel/frequency/security/signalLevel/quality/txRate）、`usb()`、`audio()`、`processes()`、`services()`、`currentLoad()`、`fullLoad()`
- 批量接口：`getStatic()` / `getAll()`（一次取全部静态数据）

### 6.2 Windows 上的硬限制（官方 Known Issues，✅ 必须写进我们的设计约束）

1. **实现已整体改为调用 PowerShell**：官方原文 "As Windows 11 also dropped wmic support, I had to move completely to powershell. Be sure that powershell version 5+ is installed."。→ 每次调用会 spawn 一个 PowerShell 进程，**单次几十~几百 ms**；几十个函数逐个调用会显著拖慢首屏。**对策：合并采集（一次性 PowerShell 脚本 / `getStatic()`）+ 全部结果缓存 + 总超时**。
2. **温度/电池等 WMI 查询需要管理员**："get-WmiObject ... sometimes needs to be run with admin privileges"；且"某些情况下返回的温度值不正确"。
3. **CPU 实时频率在 Windows/macOS 不可靠**：`cpuCurrentSpeed()` 返回恒定值（官方明说），不能用于"实时频率"展示。
4. **S.M.A.R.T. 需安装 smartmontools**（Windows 需自行下载安装）→ **绿色版不可依赖**，所以磁盘健康必须走 WMI `MSFT_StorageReliabilityCounter` 或 NWinfo 式外部工具，不能指望 `diskLayout().smartData`。
5. 编码问题已在 Windows 实现中重构规避，但要求 PowerShell 5+；老系统（Win7/8）仍可能乱码。
6. 空值/不准确：底层命令需管理员的字段在标准用户下会为空——与我们"降级为 unknown"的设计天然契合。

### 6.3 我们怎么用（栈已定：**只当参考，不直接依赖**）

- 后端是 Rust（Tauri），**Node 库无法直接调用**。它的正确用法是：作为"Windows 上每个字段该怎么取、哪些字段有什么坑"的**对照表**，指导 `scan.ps1` 的实现（本文档 §6.1/§6.2 已把结论提炼进 `检测项清单.md`）。
- **C 页签本来就不能依赖它**：TPM、Secure Boot、固件类型、DirectX/WDDM、CPU 代际白名单它都不覆盖，必须自己查注册表 / `Win32_Tpm` / dxdiag。
- **磁盘健康走 WMI**（`MSFT_StorageReliabilityCounter`/`MSFT_PhysicalDisk`），不用它的 `smartStatus/smartData`（受 smartmontools 限制，绿色版不可依赖）。
- 若未来确实需要 Node 能力，正确做法是 Tauri 的 **sidecar**（把 Node 打成外部二进制），但会显著增加体积与启动开销——**不建议**。

## 10. 风险与未验证项

1. **参考项目的成熟度**：SPECS（1 star，2026-07 创建）、System-Info-Dashboard（1 star）都是个人新项目。**只借思路，不当"业界标准"引用**；真正稳的依据是微软官方文档与 systeminformation 官方文档。
2. **权限是最大产品风险**：TPM、Secure Boot、BitLocker、原始 SMART、温度/风扇都要管理员或驱动。绿色版默认不提权 → 必须把"无法判定"设计成一等状态，**尤其 C 页的 TPM/Secure Boot：检测不到时绝不能显示"不通过"**（会误导用户以为电脑不兼容）。
3. **systeminformation 的性能与执行策略风险**：Windows 下每次调用 spawn PowerShell；企业机若限制 `ExecutionPolicy`/ConstrainedLanguage，`Get-CimInstance` 可能失败。→ 必须合并调用、给每类采集总超时、失败降级。
4. **dxdiag 成本**：一次 1~3s，且精简系统/WinPE 可能没有 dxdiag。→ 放后台阶段、设超时、失败走"型号兜底 + unknown"。
5. **杀软误报**：SID 的 README 自述 AutoIt 工具常被杀软误报；驱动类工具（LHM/NWinfo）同样有风险。→ 我们避免驱动、避免自解压、避免可疑行为；未签名 exe 在 SmartScreen 上会告警，需准备说明文案。
6. **协议合规**：SPECS/SID/systeminformation 是 MIT（借鉴实现需保留版权声明）；WhyNotWin11 是 LGPL-3.0（**不要复制其代码**）；LHM 是 MPL-2.0（进程内链接有源码可得义务）；NWinfo 是 Unlicense（最宽松）。**本项目只借鉴思路，不复制代码，风险最低**。
7. **Win10 已结束支持**（2025-10-14，❓本轮未抓取复核该日期）：C 页签应增加"OS 支持状态"提示，B 页签应有"补丁落后"警告。
8. **字体许可**：站酷小薇 / 马善政若需离线内嵌，需确认 Google Fonts 的 OFL 条款（❓本轮未核验），并与"绿色版不联网"兼容。
9. **未验证清单**：`Win32_Tpm`/`MSFT_StorageReliabilityCounter`/`WmiMonitorID` 在标准用户下的可读性、`fsutil behavior query` 是否需管理员、Win11 24H2 的 SSE4.2/POPCNT 要求是否有官方文档——这些统一列入 [`检测项清单.md`](./检测项清单.md) §7 的待验证清单，由实现阶段在真实机器上逐条确认。
10. **Tauri / WebView2 前置条件**：Tauri 用系统 WebView2 渲染，官方文档明确 Win10 1803+ / Win11 预装（<https://v2.tauri.app/start/prerequisites/> ✅）。更老的 Win10（1803 以下）或精简系统会**直接无法启动**，绿色版需在启动时检测并在报告里给出"请安装 WebView2 运行时"的提示；若要求全版本兼容，只能改用 fixed 运行时打包（体积 +100MB 以上，与绿色版体积目标冲突，**不建议**）。
11. **PowerShell 采集器的执行风险**：Rust 以 `-ExecutionPolicy Bypass -EncodedCommand` 启动 powershell，企业机若被 AppLocker/EDR 拦截或被 Defender 判定为可疑脚本，采集会整体失败 → 必须有"采集失败"兜底页 + 日志落盘，且不要拼接用户输入进脚本字符串。
